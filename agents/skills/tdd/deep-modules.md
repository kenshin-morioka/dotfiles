# 深いモジュール

「A Philosophy of Software Design」（John Ousterhout著）より：

**深いモジュール** = 小さなインターフェース + 大きな実装

```text
┌─────────────────────┐
│   小さなインターフェース   │  ← 少ないメソッド、シンプルなパラメータ
├─────────────────────┤
│                     │
│                     │
│    深い実装          │  ← 複雑なロジックが隠蔽されている
│                     │
│                     │
└─────────────────────┘
```

**浅いモジュール** = 大きなインターフェース + 少ない実装（避けるべき）

```text
┌─────────────────────────────────┐
│       大きなインターフェース           │  ← 多いメソッド、複雑なパラメータ
├─────────────────────────────────┤
│  薄い実装                        │  ← ただ素通りするだけ
└─────────────────────────────────┘
```

インターフェース設計時に自問すべきこと：

- メソッド数を減らせないか？
- パラメータをシンプルにできないか？
- 内部にもっと複雑さを隠蔽できないか？

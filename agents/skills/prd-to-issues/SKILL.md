# PRDからIssueへの分解

PRDを垂直スライス（トレーサーバレット）方式で、独立して着手可能なGitHub Issueに分解します。

## プロセス

### 1. PRDの取得

ユーザーにPRDの場所を聞いてください（リポジトリ内のファイルパス、GitHub Issue番号、URL等）。

PRDがまだコンテキストウィンドウにない場合は、該当するファイルを読み込むか `gh issue view <番号>` で取得してください。

### 2. コードベースの調査（任意）

まだコードベースを調査していない場合は、コードの現状を把握するために調査してください。

### 3. 垂直スライスの下書き

PRDを**トレーサーバレット**方式のIssueに分解してください。各Issueは全ての統合レイヤーをエンドツーエンドで貫通する薄い垂直スライスであり、1つのレイヤーの水平スライスではありません。

スライスは「HITL」または「AFK」のいずれかです。HITLスライスはアーキテクチャ上の決定やデザインレビューなど人間の判断が必要なものです。AFKスライスは人間の介入なしに実装・マージ可能なものです。可能な限りAFKを優先してください。

<vertical-slice-rules>
- 各スライスは PRD に存在する全レイヤー（例: スキーマ、API、UI、テスト）を貫通する狭いが完全なパスを提供する。PRD にないレイヤー（UI のない CLI 機能の UI 等）は要求しない
- 完了したスライスは単独でデモまたは検証が可能である
- 少数の厚いスライスよりも、多数の薄いスライスを優先する
</vertical-slice-rules>

### 4. ユーザーへの確認

提案した分解を番号付きリストで提示してください。各スライスについて以下を示します：

- **タイトル**: 短い説明的な名前
- **タイプ**: HITL / AFK
- **ブロッカー**: 先に完了する必要がある他のスライス（ある場合）
- **対応するユーザーストーリー**: PRDのどのユーザーストーリーに対応するか

ユーザーに以下を確認してください：

- 粒度は適切か？（粗すぎ / 細かすぎ）
- 依存関係は正しいか？
- さらに統合または分割すべきスライスはあるか？
- HITLとAFKの分類は正しいか？

ユーザーが承認するまで反復してください。

### 5. タスクの作成

承認された各スライスについて、タスクを作成してください。

タスクの作成先は、プロジェクトのルール（CLAUDE.md等）にタスク管理のルールが記載されていればそれに従ってください。記載がなければユーザーに確認してください（GitHub Issue、リポジトリ内ファイル、その他）。

GitHub Issueの場合は `gh issue create` を使用し、依存順（ブロッカーを先に）で作成してください。リポジトリ内ファイルの場合はMarkdownで保存してください。

以下のテンプレートを使用してください（出力先に応じてフォーマットを調整すること）。

<issue-template>
## 親PRD

PRDへのリンクまたはファイルパス

## 構築内容

この垂直スライスの簡潔な説明。レイヤーごとの実装ではなく、エンドツーエンドの振る舞いを記述してください。親PRDの特定セクションを参照し、内容を複製しないでください。

## 受入基準

- [ ] 基準1
- [ ] 基準2
- [ ] 基準3

## ブロッカー

- ブロッカーとなるタスクへの参照（ある場合）

ブロッカーがない場合は「なし - すぐに着手可能」と記載。

## 対応するユーザーストーリー

親PRDからの番号で参照：

- ユーザーストーリー3
- ユーザーストーリー7

</issue-template>

親PRDのIssueはクローズや変更をしないでください。

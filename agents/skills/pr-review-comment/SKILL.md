# PR レビュー & コメント投稿スキル

PR をレビューし、指摘をユーザー本人の文体で PR にインラインコメント投稿する。

## Step 1: 対象の取得

1. `gh pr view <URL/番号> --json title,body,author,baseRefName,headRefName,headRefOid,state,additions,deletions,changedFiles` で概要取得
2. `gh pr diff <URL/番号>` で diff 取得（大きい場合は persisted-output のファイルパスを使う）
3. PR 本文（Why/What）と diff の整合も確認する（例: 「削除した」とあるのに deletions が 0）

## Step 2: プロジェクトルールの読み込み

レビュー基準として、変更ファイルに該当するプロジェクトのコーディングルールを読み込む:

- リポジトリの `CLAUDE.md` と、そこから参照されるドキュメント
- `.claude/rules/` 配下で変更ファイルの paths に該当するもの（例: spec 変更なら `.claude/rules/spec/`）

## Step 3: 並列レビュー

diff をファイル境界で分割（目安: 1チャンク 20 ファイル前後 / 40KB 前後。小さい PR なら分割せず自分でレビュー）し、`general-purpose` エージェントを並列起動する。各エージェントへのプロンプトに必ず含めること:

- チャンクの diff ファイルパス（Read させる）
- Step 2 で読んだプロジェクトルールの要約
- レビュー観点:
  1. ルール違反
  2. テストの正しさ（実装の実際の振る舞いを検証しているか、tautological / vacuous になっていないか、過剰なモックで実質何も検証していないか、否定アサーションだけで壊れても通るテストになっていないか）
  3. flaky リスク（時刻依存、順序依存、stub 漏れ、環境依存）
  4. AI 生成コードにありがちな問題（存在しないメソッド・実装と不一致な期待値・コピペによる context 名と中身の不一致）
- **疑わしい箇所は必ず実装コードを Read して裏取りする**こと。確信が持てない指摘は「要確認」と明示させる
- 出力形式: 重要度順（重大 / 中程度 / 軽微）+ ファイルパス + 根拠

結果を統合し、重複を除いて重要度順にユーザーへ報告する。

## Step 4: コメント案の作成

報告した指摘からコメントを作る。**投稿するのは重大〜中程度の指摘に絞る（目安 10 件以内）**。軽微・スタイルは口頭報告に留めるか、聞かれたら出す。

### 文体ルール（ユーザー本人の文体）

- ラベル: 質問は `[ASK]`、意見・提案は `[IMO]`、細かい指摘は `[nits]` を1行目に置く。テストが機能していない等の強めの指摘はラベルなし
- 語尾: 断定せず「〜そうです」「〜な気がします」「〜かなと思いました」「〜して欲しいです」「〜ませんか？」
- 短く。1コメント2〜4文。箇条書き・見出し・網羅列挙は使わない（AI 感が出る）
- コード参照はバッククォート。必要なら GitHub の行リンクを貼る
- 絵文字はたまに 🙇‍♂️ 🙆‍♂️ 程度。多用しない
- 「重大」「中程度」などの重要度ラベルをコメントに書かない

### 投稿前の必須確認

**コメント案（対象ファイル:行 + 本文）を全件ユーザーに提示し、承認を得るまで絶対に投稿しない。**

## Step 5: 投稿

承認後、1つのレビューにまとめて投稿する:

1. 各コメントの `line` を PR head のファイル実体（`gh api "repos/<owner>/<repo>/contents/<path>?ref=<headRefOid>"`）で確認する。行は diff のハンク内（追加・変更行）にある必要がある
2. JSON を組み立てて投稿:

```bash
gh api repos/<owner>/<repo>/pulls/<num>/reviews --input review.json
```

```json
{
  "commit_id": "<headRefOid>",
  "event": "COMMENT",
  "body": "コメントしました",
  "comments": [
    { "path": "...", "line": 123, "side": "RIGHT", "body": "..." }
  ]
}
```

- レビュー本文（body）は「コメントしました」固定
- 行がハンク外で API がエラーになったら、diff を見て近くの変更行に付け替える

投稿後、レビューの `html_url` をユーザーに報告する。
